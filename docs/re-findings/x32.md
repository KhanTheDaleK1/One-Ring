# Clean-Room Interoperability Specification: Behringer X32 / Midas M32 OSC Control

> **Clean-Room Notice:** This document is a strictly clean-room interoperability specification describing
> the public OSC control surface of the Behringer X32 (and the closely related Midas M32) digital mixing
> console. It documents only wire framing, UDP transport, OSC address paths, argument types, ranges,
> scaling laws, and connection state rules required for an independent controller. It contains **zero
> copied source code, decompiled functions, proprietary assets, or vendor SDK code**.

---

## 1. Architecture Overview

The X32 exposes a single, unauthenticated **OSC 1.0 over UDP** control plane on port **`10023`**.

| Property | Value |
| :--- | :--- |
| Transport | UDP (unicast request/response + asynchronous push) |
| Default port | `10023` (configurable on the console's network page) |
| Encoding | OSC 1.0, big-endian, 4-byte aligned |
| Authentication | None (network isolation is the security boundary) |
| Discovery | None built in — use static IP/DHCP reservation or `/xinfo` identity probe |
| Keepalive | `GET /xremote` equivalent: the `/xremote` OSC message, refreshed every **< 10 s** |

The console has two traffic modes:

1. **Command mode** — the controller sends an OSC message and, for most parameter writes, the console
   applies it silently (no reply).
2. **Subscription mode** — after the controller sends `/xremote`, the console pushes every parameter
   change made on the console (by a human or another controller) back to the subscriber's IP/port for
   as long as the subscription is refreshed. Without `/xremote`, the controller is write-only and its
   local state will drift from the physical console.

One Ring must always run a keepalive task per X32 device. Recommended interval: **8 s** (safe margin
under the 10 s expiry).

## 2. OSC 1.0 Framing

Every OSC packet is a sequence of **null-terminated, 4-byte-aligned** fields:

```text
+---------------------------+
| OSC address (ASCII)       |  e.g. "/ch/01/mix/fader"
| 0x00 padding to 4 bytes   |
+---------------------------+
| Type tag string (ASCII)   |  e.g. ",f" / ",i" / ",s" / ",b"
| 0x00 padding to 4 bytes   |
+---------------------------+
| Argument 0 (4/8/n bytes)  |
| padding to 4 bytes        |
+---------------------------+
| Argument 1 ...            |
+---------------------------+
```

### 2.1 String Padding Rules

A string of length `N` occupies `ceil((N + 1) / 4) * 4` bytes: the bytes themselves, **at least one
`0x00` terminator**, then additional `0x00` bytes until the total is a multiple of 4.

Examples:

| String | Raw length | Padded length | Bytes after the text |
| :--- | ---: | ---: | :--- |
| `/xremote` | 8 | 12 | `00 00 00 00` |
| `/` | 1 | 4 | `00 00 00` |
| `/ch/01/mix/fader` | 16 | 20 | `00 00 00 00` |
| `/dca/1/on` | 9 | 12 | `00 00 00` |

### 2.2 Type Tags Used by the X32

| Tag | Meaning | Payload |
| :--- | :--- | :--- |
| `i` | `int32` | 4 bytes, big-endian, two's complement |
| `f` | `float32` | 4 bytes, big-endian IEEE-754 |
| `s` | OSC string | padded ASCII/UTF-8 as above |
| `b` | OSC blob | 4-byte big-endian length, then bytes, then pad to 4 |

The type tag string always begins with `,`. A message with no arguments still carries the four-byte
string `",\0\0\0"`.

> **Blob caveat:** the outer OSC blob length is big-endian per OSC 1.0, but the X32's `/meters/*`
> meter payload contains its own **little-endian** `uint32` count. See §7.

## 3. Keepalive, Identity & Status

| Message | Args | Direction | Meaning |
| :--- | :--- | :--- | :--- |
| `/xremote` | none | Controller → Console | Subscribe to asynchronous parameter updates. Refresh every < 10 s. Idempotent. |
| `/xinfo` | none | Controller → Console | Request identity/version. Console replies with one `,s` argument (e.g. firmware/identity string). |
| `/info` | none | Console → Controller | Identity/description string, usually sent in response to `/xinfo`. |
| `/status` | none | Console → Controller | Human-readable status string. |
| `/xremote` reply | none | — | No reply; success is inferred from subsequent push traffic. |

Recommended startup sequence:

1. Send `/xinfo` and wait briefly for `/info` to confirm the target is an X32/M32.
2. Send `/xremote` and schedule a refresh every 8 s.
3. Read the current values you care about (faders, mutes, scene) — the console does **not** dump full
   state automatically on subscribe.

## 4. Address Conventions

### 4.1 Channel Paths

`NN` is the zero-padded channel number, `01`–`32`. (Aux/USB/FX returns use separate address families
and are out of scope for the first One Ring release.)

| Path | Type | Range | Notes |
| :--- | :--- | :--- | :--- |
| `/ch/NN/mix/fader` | `f` | `0.0`–`1.0` | Fader position; non-linear in dB (see §5). |
| `/ch/NN/mix/on` | `i` | `0` / `1` | Channel mute/on. **1 = on**, **0 = muted**. |
| `/ch/NN/mix/pan` | `f` | `-1.0`–`1.0` | Pan. |
| `/ch/NN/mix/mono` | `i` | `0` / `1` | Mono mode. |
| `/ch/NN/mix/level` | `f` | dB | Some firmware exposes a dB setter; prefer `/mix/fader`. |
| `/ch/NN/config/name` | `s` | ≤ 12 chars | Channel name. |
| `/ch/NN/config/color` | `i` | 0–15 | Channel color index. |
| `/ch/NN/preamp/gain` | `f` | dB | Input gain (not available on all source types). |
| `/ch/NN/preamp/phantom` | `i` | `0` / `1` | +48 V phantom power. |

### 4.2 DCA Paths

`N` is the DCA number `1`–`8` (no zero padding).

| Path | Type | Range | Notes |
| :--- | :--- | :--- | :--- |
| `/dca/N/fader` | `f` | `0.0`–`1.0` | DCA fader. |
| `/dca/N/on` | `i` | `0` / `1` | DCA mute/on. **1 = on**, **0 = muted**. |
| `/dca/N/config/name` | `s` | ≤ 12 chars | DCA name. |

### 4.3 Main / Bus Paths

| Path | Type | Range | Notes |
| :--- | :--- | :--- | :--- |
| `/main/st/mix/fader` | `f` | `0.0`–`1.0` | Stereo main fader. |
| `/main/st/mix/on` | `i` | `0` / `1` | Stereo main mute/on. |
| `/main/m/mix/fader` | `f` | `0.0`–`1.0` | Mono main fader (if enabled). |
| `/main/m/mix/on` | `i` | `0` / `1` | Mono main mute/on. |
| `/bus/N/mix/fader` | `f` | `0.0`–`1.0` | Mix bus `N` (1–16). |
| `/bus/N/mix/on` | `i` | `0` / `1` | Mix bus mute/on. |

### 4.4 Scene / Snippet Actions

| Path | Type | Range | Notes |
| :--- | :--- | :--- | :--- |
| `/-action/goscene` | `i` | `1`–`100` | Recall console scene by index. |
| `/-action/gosnippet` | `i` | `1`–`100` | Recall snippet by index. |
| `/-action/goscene` (query) | — | — | No query form; read `/-show/...` state if needed. |

Scene recall is a **high-impact** action: it can move many faders, mutes, routing assignments, and
preamp gains at once. One Ring must treat it as Tier 2 (two-step confirmation) and snapshot the
affected DCAs/channels first.

## 5. Fader Position ↔ dB Law

The X32 fader float is **not** linear in dB. The interoperability baseline used by One Ring is:

- `f = 0.0` → `-∞` (off)
- `f = 0.75` → `0.0 dB` (unity)
- `f = 1.0` → `+10.0 dB`

A monotonic exponential fit that satisfies those anchors:

```text
dB(f) = 80.04 * log10(f / 0.75)          for f > 0
f(dB) = 0.75 * 10^(dB / 80.04)           for dB > -90, else 0.0
```

where `80.04 ≈ 10 / log10(4/3)`.

Sample values:

| Fader float | Approx. dB |
| ---: | ---: |
| `0.0000` | `-∞` |
| `0.0625` | `-86.1` |
| `0.1250` | `-62.0` |
| `0.2500` | `-38.1` |
| `0.5000` | `-14.1` |
| `0.6250` | `-6.3` |
| `0.7500` | `0.0` |
| `0.8750` | `+5.0` |
| `1.0000` | `+10.0` |

> **Calibration note:** the exact taper is firmware-dependent and the anchors above are the
> interoperability contract, not a claim about the console's internal lookup table. If a venue's
> console measures differently, calibrate the two constants (`UNITY = 0.75`, `DB_PER_DECADE = 80.04`)
> per device rather than editing call sites. Never expose raw fader floats to volunteers; always
> present dB.

## 6. Metering: `/meters/1`

The console pushes meter frames to subscribed controllers at roughly **10–30 Hz** (firmware and load
dependent). The OSC message is:

```text
address: "/meters/1"
tags:    ",b"
blob:    [uint32 LE count][count × uint8 level]
```

- The OSC blob length is big-endian (OSC 1.0).
- The **first four bytes inside the blob are little-endian** and give the number of following meter
  bytes.
- Each level byte is a **linear peak magnitude**, `0..=255`, where `0` means silence/`-∞` and `255`
  means full scale (`0 dBFS`).

Conversion used by One Ring:

```text
dBFS(v) = 20 * log10(v / 255)      for v > 0
dBFS(0) = -∞
```

| Byte | Approx. dBFS |
| ---: | ---: |
| `255` | `0.0` |
| `128` | `-6.0` |
| `64` | `-12.0` |
| `32` | `-18.1` |
| `16` | `-24.0` |
| `8` | `-30.0` |
| `1` | `-48.1` |
| `0` | `-∞` |

Meter channel ordering follows the console's meter bank layout (channel meters first, then buses/DCAs
depending on `/meters/1` vs `/meters/2`). Do **not** assume a fixed count; always read the embedded
`count` field.

> **Verification item:** if captures show a pre-scaled/curve-mapped byte rather than linear amplitude,
> replace only `meter_byte_to_db()`; the framing and count parser remain valid.

## 8. Connection Health & Reconnect

| Signal | Interpretation |
| :--- | :--- |
| `/info` reply after `/xinfo` | Console reachable and identified. |
| Push traffic after `/xremote` | Subscription healthy. |
| No push traffic for > 10 s while console is known-active | Subscription expired or network path lost — reconnect. |
| UDP send succeeds with no replies | Not proof of liveness (UDP is fire-and-forget). Track last `/info`/push timestamp. |

Reconnect policy for One Ring: exponential backoff `500 ms → 1 s → 2 s → 4 s → 15 s` with jitter,
re-send `/xinfo` then `/xremote`, and re-read the parameters that matter for the current show before
allowing destructive writes.

---

## 9. Safety Rules for One Ring

1. **Never trust local state on reconnect.** Re-read faders/mutes/scene before showing green.
2. **Enforce guards in the backend, not the UI.** `Main LR` mute, scene recall, and preamp/phantom
   changes must require an explicit confirmation token from the cue engine.
3. **Clamp volunteer trims** to the engineer-defined `min_db`/`max_db` before converting to a fader
   float.
4. **Debounce fader writes** (≥ 30–50 ms) and coalesce to the latest value; the console can be
   overwhelmed by high-rate OSC streams.
5. **Meter-driven truth.** "Unmuted" is not "signal present." Use `/meters/1` to distinguish a live
   pastor mic from a muted beltpack or dead battery.

---

## 10. Integration Recommendations for One Ring

- `crates/ring-x32` / `src-tauri/src/protocols/x32.rs` owns the OSC codec and fader law.
- One keepalive task per console, shared by all cue/UI writes.
- Read-only discovery first (`/xinfo`), then subscribe (`/xremote`), then enable writes.
- Map volunteer-facing DCAs to named groups (Pastor, Band, Media, Main LR) and keep raw channel
  faders in Engineer Mode only.
- Expose `scene_recall` and `main_mute` as destructive actions with confirmation tokens.
- Feed meter bytes into the same `meter://` event bus as Dante/NDI so the UI has one meter model.
